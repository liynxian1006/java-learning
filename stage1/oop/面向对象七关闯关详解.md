## 第 1 关 · 类与对象

📄 `L1_ClassAndObject.java`

### 核心区分
| | 类 | 对象 |
|---|---|---|
| 是什么 | 模板/蓝图纸 | 按模板造出来的具体东西 |
| 例子 | `Student` | `new Student("张三", 21, "计算机")` |
| 代码 | `Student`（类型名） | `new Student(...)`（表达式） |

### 关键认知 1：声明 ≠ 创建
```java
Student s1 = null;     // 声明了变量，但没有对象
s1.introduce();        // → NullPointerException
```
局部变量必须先赋值才能用。`null` 表示"引用指向空"。

### 关键认知 2：变量里存的是**地址**
```java
Student s3 = s1;       // 赋值的是地址，不是复制对象
s3.age = 99;
System.out.println(s1.age);   // → 99！s1 也变了
```
**这就是"引用传递"**。以后遇到"我改了副本为什么原对象也变了"，答案就在这里。

### 关键认知 3：对象数据互相独立
```java
s1.age = 22;           // 不影响 s2
```
每个对象有自己的一份成员变量副本。

### 关键认知 4：L1 的 Student 现在也写了空参构造
```java
Student() { }                              // ← 给框架用
Student(String name, int age, String major) { ... }   // ← 手动 new 用
```
两个都写才是实体类的规范写法。原因见下方「构造方法专题」。

L1 的 ⑤-2 段落专门演示了空参构造的用途：
```
⑤-2 空参构造的用途（框架就是这么造对象的）
    大家好，我叫钱七，今年23岁
    → MyBatis / Spring 就是这样：反射 new 空对象 + setter 逐个赋值
    → 所以实体类规范上，无参构造和有参构造【都要写】
```

## 第 2 关 · 封装

📄 `L2_Encapsulation.java`

### 为什么必须封装
```java
// 不封装（public 字段）：能编译、运行时也不报错，但数据已经错了
s.age = -5;    // 错误数据进系统，几周后才暴露

// 封装（private + setter）：当场拦下
s.setAge(-5); // 输出 "[校验不通过] 年龄必须在 0-150 之间，已忽略"
```

### 铁律
1. **数据一律 `private`**
2. 需要对外暴露的才开 `public` getter/setter
3. **setter 才是校验的重点**，getter 通常只读
4. **构造方法内部也走 setter**，别直接写 `this.age = age`（否则校验被绕过）

```java
public Student(String name, int age, String major) {
    setName(name);     // ← 走 setter
    setAge(age);
    setMajor(major);
}
```

### 面试怎么答
> "封装是用访问修饰符把数据藏起来，只通过方法对外提供受控的访问入口。好处有三：一是控制访问权限，避免外部随意篡改；二是在 setter 里做参数校验，把非法数据挡在系统外；三是未来给字段加逻辑时，不破坏已有调用方的兼容性。"

**项目映射**：你项目二的 `Student.java`、项目三的 `entity/Student.java` 全是这个写法。

## 第 3 关 · 继承

📄 `L3_Inheritance.java`

### 三个必会
```java
class Student extends Person {     // ① extends 继承
    public Student(...) {
        super(name, age);          // ② super(...) 调父类构造，必须是第一句
    }
    @Override
    public void speak() { ... }    // ③ @Override 重写父类方法
}
```

### 构造顺序：父类先，子类后
```
new Student(...)  →  Person 构造执行  →  Student 构造执行
```

### ⚠️ 重写 vs 重载（最高频面试题）

| | 重写 Override | 重载 Overload |
|---|---|---|
| 场景 | 子类改父类已有的方法 | 同一个类里多个同名方法 |
| 方法名 | 必须相同 | 必须相同 |
| 参数列表 | **必须相同** | **必须不同**（个数或类型） |
| 关系 | 父子类之间 | 与继承无关 |
| 返回值 | 必须相同（或协变） | 可以不同 |

```java
// 重载示例（同类多个同名不同参）
int    add(int a, int b)
int    add(int a, int b, int c)
double add(double a, double b)
```

### protected 的作用
`protected` = **子类可以访问，外部类不行**。父类的成员变量常用它。

### 向下转型 + instanceof
```java
if (p2 instanceof Teacher) {
    System.out.println(((Teacher) p2).getTitle());
}
```
先判断真实类型，再强转取子类特有属性。

**项目映射**：项目二的 `Job`/`InternshipJob`、项目三的 `Service` 继承体系。

## 第 4 关 · 多态

📄 `L4_Polymorphism.java`

### 三个前提（缺一不可）
1. 父类/接口引用指向子类对象（向上转型）
2. 父类方法被子类重写（`@Override`）
3. 运行时按对象**真实类型**决定执行哪个版本

### 面试金句
> **编译看左，运行看右。**
> 编译期看变量声明的类型（决定能调哪些方法），运行期看对象的真实类型（决定执行哪个方法）。

```java
Channel c1 = new OnlineChannel(100.0);
c1.process();   // 编译看 Channel，运行看 OnlineChannel
```

### 多态的真正价值
```java
List<Channel> channels = new ArrayList<>();
channels.add(new OnlineChannel(200.0));
channels.add(new OfflineChannel("海淀路 1 号"));

for (Channel ch : channels) {
    ch.process();    // ← 一行代码处理所有类型
}
```
**没有多态**的话，这里要写一串 `if (ch instanceof OnlineChannel) {...} else if (...)`。

### 多态的代价
父类引用**看不见**子类特有成员：
```java
Channel c1 = new OnlineChannel(100.0);
c1.getAmount();    // ❌ 编译报错，Channel 没这个方法
((OnlineChannel) c1).getAmount();   // ✅ 强转后才行
```

**项目映射**：Spring 的依赖注入本质就是多态——你注入 `StudentService`，运行时执行的是 Spring 容器里那个具体实现。

## 第 5 关 · 抽象类

📄 `L5_AbstractClass.java`

### 核心
```java
abstract class Job {
    public abstract double calcSalary();   // 抽象方法，无方法体
    public void display() { ... }          // 具体方法，所有子类共通
}
new Job("普通岗位", 10000);   // ❌ 编译报错：Job is abstract; cannot be instantiated
```

### 抽象类的设计思想
> **把「不变的」放父类（复用），把「变化的」留给子类（多态）。**

- `display()` 所有岗位都一样 → 父类统一实现，不让子类重复写
- `calcSalary()` 各岗位算法不同 → 抽象方法，强制子类补齐差异

### 抽象方法的三条限制
| 限制 | 原因 |
|---|---|
| 不能 `private` | 否则子类无法重写 |
| 不能 `static` | 静态方法不参与多态 |
| 不能 `final` | 否则子类无法重写 |

### 抽象类可以有构造方法
虽然不能 `new`，但子类 `extends` 时通过 `super(...)` 调用它，父类的初始化逻辑照样执行。

## 第 6 关 · 接口

📄 `L6_Interface.java`

### 核心
接口描述"**一类事物应该具备什么能力**"，只说能做什么，不规定怎么做。

```java
interface ApplicationStatus {
    String PENDING = "待审核";      // 默认 public static final
    void advance();                 // 默认 public abstract
    default boolean isFinal() { return false; }   // Java 8+ 可有默认实现
}
```

### 规则
- ❌ 不能有构造方法（不能 `new`）
- ✅ 成员变量默认 `public static final`（常量）
- ✅ 方法默认 `public abstract`，也可加 `default` / `static` 具体方法
- ✅ 一个类可实现**多个**接口，接口之间也可多继承

### ⚠️ 抽象类 vs 接口（面试必背）

| | 抽象类 | 接口 |
|---|---|---|
| 构造方法 | 可以有 | 不能有 |
| 成员变量 | 可以有 | 只有常量 |
| 具体方法 | 可以有 | 可有 default |
| 继承数量 | 单继承 | 多实现 |
| 设计意图 | 「is-a」共性抽象 | 「has-a」能力契约 |
| 使用场景 | 一系列类共享代码和结构 | 给不相关的类加同一套能力 |

**怎么选？** 两者都是"父子共性"→ 用抽象类；"能力契约"（可能不相关）→ 用接口。

**项目映射**：你项目三的 `StudentMapper` 就是接口——**没有实现类**，MyBatis 用动态代理在运行时生成。这正是接口的典型用法：定义契约，实现交给框架。

## 第 7 关 · 综合实战

📄 `L7_OopFinal.java` —— 迷你版校园招聘系统，把前 6 关全部串起来。

### 六大概念的落点
| 概念 | 在哪 |
|---|---|
| 封装 | `Student` 的 private 字段 + setter 校验（姓名空、年龄负数当场抛异常） |
| 继承 | `Job` → `InternshipJob` / `FullTimeJob` / `SearchableJob` |
| 多态 | `for (Job job : jobs) job.display()` — 薪资算法各不相同 |
| 抽象 | `Job` 是 abstract，不能 new，只声明 `calcSalary()` |
| 接口 | `Searchable`（可搜索）、`Rechargeable`（可充值），可多实现 |
| 组合 | `Application` 持有 `Student` + `Job` 两个对象的引用 |

### 组合 vs 继承（进阶认知）
```java
class Application {
    private final Student student;   // 组合：持有
    private final Job job;
}
```
**组合优于继承**：继承是"is-a"（is-a Student），组合是"has-a"（has a Student）。
Java 单继承，用组合可以表达更复杂的关系，且耦合更低、更灵活。

### 多态的实际收益（第 7 关 ⑤ 的输出）
```
全部岗位平均薪资：22600.00 元
→ 服务层完全不知道有实习岗/全职岗/算法岗的区别，全靠多态
→ 新增岗位类型，服务层一行不改（开闭原则）
```

## 专题 · 空参构造到底要不要写？

📄 `L8_ConstructorTopic.java`（可运行）　📄 `L8_ConstructorErrorDemo.java`（可运行，运行时复现编译错误）

### 结论
> **只要写了任何一个有参构造，Java 就不会再自动生成空参构造。此时 `new Xxx()` 直接编译报错。**

### 三种情况
| 写法 | 有空参构造吗 | `new Xxx()` |
|---|---|---|
| 一个构造都不写 | ✅ 编译器自动补 | ✅ 可以 |
| 只写有参构造 | ❌ **不再自动补** | ❌ 编译报错 |
| 无参 + 有参都写 | ✅ 显式写了 | ✅ 可以 |

### 为什么项目里必须写（核心原因）

框架造对象的流程是这样的（MyBatis 查库 → 转对象）：
```
1) 反射 new Student()          ← 必须有无参构造！
2) rs.getString("name") 读一列
3) student.setName(值)         ← 逐个塞值
4) 返回这个对象
```
**第 1 步就依赖无参构造**。如果没有，框架直接抛：
```
java.lang.NoSuchMethodException: <init>()
```

同样的道理适用于：
- **Spring 注入**（`@Autowired` 字段注入）
- **Jackson 反序列化**（`@RequestBody` 接 JSON）
- 几乎所有 ORM / 序列化框架

> 所以你项目二、三的实体类**都写了空参构造**，那不是冗余，是刚需：
> ```java
> // 项目三 entity/Student.java
> public Student() {                                    // ← 框架用
> }
> public Student(Integer id, String name, ...) { }      // ← 手动 new 用
> ```

### 反射实测（专题程序里真跑了一遍）
```
反射 newInstance() 成功 → 反射创建的学生
→ 证明：框架确实是用「无参构造 + setter」两步走
OnlyFullArg 反射找无参构造 → NoSuchMethodException
→ 这就是框架报错的真实原因
```

### 继承中的 super 规则
父类**只有有参构造**时，子类必须显式 `super(参数)`，否则隐式 `super()` 找不到父类无参构造 → 编译报错。

`L8_ConstructorErrorDemo.java` 用反射在运行时复现了这条错误：
```
无法将类 BaseOnlyFullArg 中的构造器 BaseOnlyFullArg应用到给定类型;
  需要: java.lang.String
  找到:    没有参数
  原因: 实际参数表和形参表长度不同
```
> 为什么不直接写那个错误？——写出来就编译不过，IDEA 会常驻一个红叉，容易被误认为"代码写坏了"。用反射运行时复现，演示效果一样但不影响正常学习。

三种修法任选其一：
1. 给父类加一个无参构造（最常用）
2. 子类显式写 `super("参数")`
3. 删掉子类的无参构造，只保留带参的

### 面试怎么答
> "Java 只在类中一个构造方法都没写时，才自动生成默认的无参构造。一旦写了有参构造，编译器就不再补空参构造了。所以实体类规范上要显式写出无参构造——因为 MyBatis、Spring、Jackson 这些框架都是通过反射调用无参构造创建对象，再用 setter 逐个填充属性。如果实体类只有有参构造，框架在运行时会抛 NoSuchMethodException。"
