# 项目 ①：校园信息管理系统（Python + Flask）

## 1. 数据库设计（3 张表，已写在 `db_init.sql`）
```sql
user(id, username, password, role)            -- 登录账号
student(id, name, gender, major, grade)       -- 学生
course(id, name, teacher, credit)             -- 课程
```
用 **Navicat** 建库建表（默认数据库操作用 Navicat）：
1. 连接 localhost 的 MySQL（root + 你的密码）。
2. 新建查询，把 `db_init.sql` 整段执行 → 自动建 `campus_db` 和 3 张表。

## 2. 文件结构与职责（都在 `flask-campus-system/`）
| 文件 | 作用 |
|---|---|
| `app.py` | Flask 后端：6 个接口 + 数据库配置 |
| `db_init.sql` | 建库建表脚本 |
| `requirements.txt` | 依赖清单（flask / pymysql / flask-cors） |

## 3. 运行步骤
```bash
cd flask-campus-system
pip install -r requirements.txt     # 装依赖
# 用 Navicat 执行 db_init.sql 建库建表
# 打开 app.py，把 DB_CONFIG 的 "password": "你的密码" 改成真实密码
python app.py                       # 启动，访问 http://localhost:5000
```

## 4. 接口清单与测试（用 curl 或 Postman）
| 方法 | 路径 | 请求体 / 说明 |
|---|---|---|
| POST | `/login` | `{"username":"xxx","password":"yyy"}` 登录校验 |
| POST | `/student/add` | `{"name":"张三","gender":"男","major":"CS","grade":"2024"}` |
| GET | `/student/list` | 返回全部学生 |
| POST | `/student/update` | 同上 + `"id":1` |
| POST | `/student/delete` | `{"id":1}` |
| GET | `/course/list` | 返回全部课程 |

测试示例（curl）：
```bash
curl -X POST http://localhost:5000/student/add -H "Content-Type: application/json" \
  -d "{\"name\":\"张三\",\"gender\":\"男\",\"major\":\"CS\",\"grade\":\"2024\"}"
curl http://localhost:5000/student/list
```

## 5. 这段代码体现了什么（面试能讲）
- **路由配置**：`@app.route` 把 URL 映射到函数（对应简历"路由配置"）。
- **前后端分离**：返回 `jsonify`（JSON），前端可独立开发。
- **分层雏形**：`get_conn()` 统一管数据库连接，每个接口"开连接→执行→finally 关连接"，这正是阶段 1 学的异常处理 + JDBC 思想。
- **CORS**：`flask_cors` 允许浏览器跨域调用。

## 6. 可扩展点（加分项）
- 加 JWT 登录鉴权；给列表加分页；密码改存哈希（bcrypt）。

# 项目 ②：校园实习就业信息管理系统（Java 17 + JDBC）

## 1. 数据库设计（4 张表，已写在 `schema.sql`）
```
student(id, name, major, phone)         -- 学生
company(id, name, industry)             -- 公司
job(id, company_id, title, salary, major_required) -- 岗位
application(id, student_id, job_id, status)        -- 投递记录
```
同样用 **Navicat** 执行 `schema.sql` 建库建表（`campus_job_db`）。

## 2. 分层架构（这是本项目最大的学习价值）
```
src/com/campus/
  util/DBUtil.java      → 数据库连接工具（统一封装连接与异常）
  entity/               → 实体类：Student / Company / Job / Application（对应数据库表）
  dao/                  → 数据访问层：StudentDao / JobDao / ApplicationDao（写 SQL）
  service/              → 业务层：StudentService（组合多个 dao 调用）
  Main.java             → 控制台演示入口（阶段 3 会被 Spring 的 Controller 替代）
```
**为什么分层**（简历"理解分层，注重可读性与可维护性"的来源）：
- `entity`：数据长什么样（表 → Java 对象）。
- `dao`：怎么和数据库打交道（增删改查 SQL），不掺业务。
- `service`：业务规则放这里，调用 dao，给上层用。
- 好处：改 SQL 只动 dao，改业务只动 service，互不干扰。

## 3. 运行步骤（用 IDEA，最省心）
1. 用 **Navicat** 执行 `schema.sql` 建库建表。
2. IDEA 打开 `java-jdbc-campus-system` 文件夹。
3. 加 JDBC 驱动：下载 `mysql-connector-j-8.x.jar`，菜单 **File → Project Structure → Libraries → ＋ → 选 jar**。
   （偷懒法：打开 `DBUtil.java`，`Class.forName(...)` 标红处按 `Alt+Enter` 下载驱动。）
4. 打开 `src/com/campus/util/DBUtil.java`，把
   `private static final String PASSWORD = "你的密码";` 改成真实密码。
5. 右键 `Main.java` → **Run 'Main'**。控制台打印"新增影响行数：1"和一行学生数据即成功。

## 4. 已涵盖功能（8+，写在各 Dao 里）
- 学生：add / list / update / delete
- 岗位：add / 分页查询 `pageQuery` / 按专业筛选 / 按薪资筛选
- 投递：apply / 状态流转 `updateStatus` / 按学生查询

> 当前 `Main.java` 只演示了"新增学生 + 查询列表"两条；其余功能已在 Dao 中实现，你可在 `Main` 里继续调用 `service.xxx()` 来演示。

## 5. 这段代码体现了什么（面试能讲）
- **JDBC 全流程**：加载驱动 → 获取连接 → `PreparedStatement` → 执行 → 关闭（阶段 1 学的）。
- **PreparedStatement**：用 `?` 占位防 SQL 注入。
- **分层 + 封装**：entity/dao/service 各司其职。
- **异常统一管理**：`DBUtil` 把连接异常封装好，业务层更干净。
